CURRENT BOTTLENECK

C hides repair behind toolchains. MicroPython exposes the loop.

If a user builds with C

  1. Install toolchain: Arduino core, ESP-IDF, PlatformIO, compiler, USB driver.
  2. Match board stack: SDK version, board package, flash size, pin map, libraries.
  3. Compile: fix headers, CMake, linker, flags, driver versions, memory errors.
  4. Flash and monitor: upload binary, open serial, copy logs back into chat.
  5. Repeat slowly: every small fix returns to compile -> flash -> serial.

If a user builds with MicroPython

  1. Flash runtime once: board gets a stable interpreter and REPL.
  2. Copy recipe code: Python files, driver packages, board constraints.
  3. Run on device: errors are readable stack traces and serial logs.
  4. Inspect state: REPL can query I2C scan, pin state, sensor values, memory.
  5. Patch and rerun: update one file or driver without rebuilding firmware.

Why this matters for AI: C is better for final firmware and performance, but early prototype repair is hidden across installation, compilation, flashing, and logs. MicroPython keeps more failure state visible and close to the agent.
