# Blockless 真机验收清单 (Real-Board Acceptance Checklist)

> 面向：拿到 VSIX、要在**真实开发板**上跑通一次 Blockless 的验收人员。一页纸,跟着做完 8 步。UI 名称均取自实际插件界面(不是臆造的按钮名)。

## 支持的板卡 (Supported boards)

引脚级全支持(推荐用来验收)的 6 块板卡:

- ESP32 DevKit V1
- ESP32-S3 DevKitC-1
- ESP32-C3 DevKitM-1
- ESP8266 NodeMCU
- Raspberry Pi Pico
- Pico W

其他官方 MicroPython 板卡可用,但仅"固件模式"(接线需你自己确认),不在本次验收范围内。

## 验收步骤 (Step-by-step)

| # | 操作 | 预期现象 |
|---|---|---|
| 1 | **安装插件**:VS Code → 扩展(Extensions,`Ctrl+Shift+X`)→ 右上角 `···` → **Install from VSIX…**,选中拿到的 `.vsix` 文件。 | 左侧活动栏出现 **Blockless** 图标;点开后侧边栏出现 Blockless 面板。 |
| 2 | 打开 Blockless 面板里的 **环境(Doctor)** 标签页,点 **重新检测**。 | 依次看到四项体检结果:**Python**、**依赖**、**板子**、**MicroPython**,全部变绿(✓)。任何一项不绿,按它给的提示(装 Python / 点"安装依赖" / 换驱动或数据线 / 刷固件链接)处理后再点一次"重新检测"。 |
| 3 | 在输入框上方的选板区,保持默认 **系统推荐板卡**,或切到 **自定义** 模式、在板卡列表里选中你手上这块板(6 选一)。 | 选中的板卡在列表里高亮显示为已选状态。 |
| 4 | 在底部输入框粘贴**一句话需求**(如 `让板载 LED 每隔一秒闪烁一次`),点 **生成**。 | 面板开始出现动态更新,随后出现一张**器件确认卡片**,列出计划用到的元件。 |
| 5 | 阅读器件卡片,点 **确认器件**。 | 出现下一张**方案卡片**(板子 / 元件 / 接线),点 **确认并生成**。 |
| 6 | 点 **确认并生成**。 | 生成过程中的状态提示滚动更新;**接线(Wiring)** 和 **架构图(Diagram)** 标签页出现内容。若卡住,会看到"**Build got stuck**"提示和一键重试按钮——点一下即可继续,不算失败。 |
| 7 | 出现部署确认后,插好板子,点 **部署(Deploy)**。 | 提示检测/连接到板子的串口,随后开始烧录,烧录完成后自动运行。 |
| 8 | 切到 **串口(Serial)** 标签页,同时看板子实物。 | 与第 4 步的一句话需求匹配的现象:LED 按预期闪烁 / OLED 显示文字 / 串口打印出传感器读数等。 |

## 失败时反馈什么 (What to send back on failure)

任何一步不符合"预期现象",按下面三样打包反馈到
**GitHub Issues** — https://github.com/FreakStudioCN/mpy-hardware-extension/issues:

1. **环境(Doctor)面板当前四项的状态**(截图,或把每一行的文字连同它下面的提示一起复制下来)。
2. **会话日志**:在你当前打开的工作区(项目文件夹)下找 `.mpyhw/sessions/` 目录——里面每次对话是一个子文件夹,**文件夹名就是 trace_id**,请把该文件夹里的 `session.jsonl` 一并附上。
3. **扩展输出日志**:VS Code 菜单 **查看(View) → 输出(Output)**,面板右上角下拉框选 **Blockless** 频道,把内容复制附上。

以及卡在哪一步 + 用的哪块板 + 操作系统。
