Lesson 0003 · 协议执行器

createProtocolLoop 到 runProtocolBuild：6 个工具如何驱动本地插件

本课只讲协议 loop。重点是：模型不直接操作电脑，它只能发 6 个协议工具；插件把工具调用翻译成本地 UI、文件、脚本和设备动作。

核心文件

  • src/core/protocol-build.ts：把宿主能力适配成 protocol deps。
  • src/core/protocol-loop.ts：phase loop 和工具执行。
  • src/core/protocol-registry.ts：从 contract 读取 6 个工具和路由。
  • contracts/protocol_messages.json：唯一协议契约。
  • test/protocol-loop.test.ts：最重要的插件侧协议测试。

createProtocolLoop 的角色

createProtocolLoop({
  apiBaseUrl,
  fetchImpl,
  shim,
  getAuthToken,
  readWorkspaceFile,
  writeProjectFile,
  projectRoot
}) -> loop(input)

它不是 phase 状态机。它负责创建这些适配器：LLM client、device executor、script executor、file executor。

runProtocolBuild 的角色

runProtocolBuild(input, deps):
  phase = input.startPhase ?? "analyze"
  manifest = input.startManifest ?? {}
  for each phase:
    runPhase(phase, manifest)
    if phase_complete:
      manifest = manifest_content
      phase = next_phase
    else:
      return stalled

它只推进 phase，不理解硬件业务。硬件业务来自后端 prompt、skill 和模型输出。

6 个协议工具

工具路由阻塞本地行为
approval_requestui是调用 confirmApproval，等待 WebView 回答
file_operationfs是读写项目文件
script_runhost是通过 shim 跑本地工具链脚本
device_commanddevice是通过 shim 操作 mpremote/串口
status_updatenotify否发时间线进度，自动 ack
phase_completenotify否结束 phase，携带 manifest 和 next_phase

executeProtocolTool 的判断

这个函数是防线。它会处理：

  • 未知工具名：返回 unknown_tool，不崩溃。
  • payload 已被 SSE 解析层标记 invalid：返回 protocol_payload_invalid。
  • 用户取消 approval：返回 user_cancelled。
  • 设备执行异常：返回结构化 runtime_error。
验收重点：改协议 loop 时，至少跑 node --no-warnings --experimental-strip-types --test test/protocol-loop.test.ts。它覆盖 phase advance、approval、device serial、unknown tool、cancel、stall。
