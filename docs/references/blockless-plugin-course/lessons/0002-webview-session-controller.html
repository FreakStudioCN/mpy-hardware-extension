Lesson 0002 · 插件宿主入口

WebView 到 SessionController：用户点击 Generate 后发生什么

本课只讲一件事：WebView 页面如何把用户输入交给 VS Code 扩展宿主，宿主如何用 SessionController 接管长会话。

成功标准

学完你应该能定位：按钮无响应、登录没触发、approval 卡片不返回、reset 后旧消息污染新会话这几类问题。

调用链

src/webview/index.html
  Generate button click
  -> vscode.postMessage({ type: "start_session", intent, boardId: "auto" })

src/webview/panel.ts
  webview.onDidReceiveMessage(...)
  -> checkProtocolVersion(/v1/tools)
  -> GitHub auth
  -> controller.start(...)

src/extension/session-controller.ts
  -> creates trace/state
  -> calls loop(...)
  -> forwards events back to WebView

WebView 该看什么

位置作用排查问题
index.html 的 Generate click handler取 intent，锁定语言，发 start_session按钮点了没发消息
window.addEventListener("message")接收宿主消息并渲染 UI宿主有事件但页面不更新
addApprovalPrompt渲染统一 rich approval card用户选择没回到 loop
addDeployPrompt部署前确认接线和端口部署按钮不可用、端口没选中

panel.ts 该看什么

panel.ts 是 WebView 和真实宿主能力之间的总线。它负责解析 API 地址、创建 shim、创建 GitHub auth、创建 recorder、绑定文件读写、创建 loop。

start_session 分支

这是最重要的入口。它先检查协议版本，再检查 toolchain skew，再做 GitHub 登录，最后调用 controller.start。

ui_prompt_response 分支

所有用户回答都会从这里回到 SessionController.resolvePrompt。部署确认时还会先设置端口，避免设备 tool 比端口选择更早执行。

SessionController 负责什么

机制解决的问题
pendingPrompts把 UI 卡片回答接回正在等待的 promise
AbortController取消当前 LLM/设备/脚本流程
generationreset 后丢弃旧 run 的迟到事件
stateretry 或连续输入时延续当前 phase/manifest
latestManifest/latestFiles在 headless fallback 下汇总产物写盘
判断边界：WebView 只负责展示和发消息；panel.ts 负责接 VS Code 能力；SessionController 负责会话状态，不负责决定硬件方案。
