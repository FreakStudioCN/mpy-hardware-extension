Lesson 0006 · 验收课

改完 SKILL.md 后怎么证明插件还能工作

本课只讲验收。目标是让你改 skill、phase recipe、协议 contract 或执行器后，知道该跑哪一级门槛，不靠感觉上线。

什么算 skill 改动

  • 改 third_party/MicroPython_Skills/<served-skill>/SKILL.md。
  • 改 skill_catalog.py 的 served skill 列表或 phase 映射。
  • 改 routes_llm.py 的 adapter preamble 或 _PHASE_RECIPES。
  • 改 contracts/protocol_messages.json。
  • 改 6 个协议工具的本地执行器。

第 1 级：无模型快速门

cd mpyhw-api
pytest tests/test_skill_catalog.py tests/test_protocol_contract.py tests/test_protocol_backend.py tests/test_llm_messages.py

cd ../mpy-hardware-extension
npm test
npm run typecheck

这一层不调用真实 DeepSeek，主要证明 contract、白名单、payload validation、extension 执行器没有明显断裂。

第 2 级：真实模型 analyze smoke

cd mpyhw-api
python scripts/smoke_analyze_protocol.py "做一个温湿度监测仪，温度超过阈值就让蜂鸣器报警"

通过标准：

  • GATE: PASS。
  • 所有 tool call 都在 6-tool protocol 内。
  • payload schema 有效。
  • 到达 approval_request。
  • 不以环境预检 script_run 开头。
  • 没有 raw shell smell，比如 mpremote、pip install、bash fence。

第 3 级：真实模型 headless E2E

cd mpyhw-api
python scripts/e2e_protocol.py "做一个温湿度监测仪，温度超过阈值就让蜂鸣器报警，OLED 屏幕显示读数"

通过标准：

  • E2E: PASS。
  • 没有 off-protocol tool。
  • payload validity 至少 95%。
  • 至少到达 generate。
  • 写出 firmware/main.py。
  • firmware/main.py 包含 MPYHW_READY。

第 4 级：VS Code 本地验收

cd mpy-hardware-extension
npm test
npm run typecheck
npm run package

手工检查：

  • Activity Bar 看到 Blockless。
  • 面板能打开。
  • 加载板卡列表。
  • GitHub 登录能触发。
  • credits 能显示。
  • 输入中文 intent 后能看到 approval card。
  • 确认后能看到 phase progress。
  • 生成文件落到 blockless-project。

最小验收矩阵

改动必须跑真实模型硬件
analyze skill/recipe后端静态门smoke_analyze_protocol.py不需要
generate/wiring/diagram/deploy recipe后端静态门e2e_protocol.py不需要
协议 contract后端 contract + npm test通常不需要不需要
WebView/SessionControllernpm test + typecheck不需要不需要
device shimshim 相关测试不需要建议有
发布前npm test + typecheck + package视改动建议 smoke
上线前判断：skill 改动不是“文本改了就行”。必须证明模型仍然按 6-tool protocol 说话，并且 phase 能走到 phase_complete。
