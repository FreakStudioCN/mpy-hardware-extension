Blockless 插件速查表

目标：快速判断一个问题该看哪一层、哪个文件、跑哪个验证。对应课程：Blockless 插件架构完整导览。工程验收文档：docs/plugin-architecture-and-skill-acceptance.md。

一张心智图

package.json 声明 VS Code 贡献点：Activity Bar 容器、Webview View、命令、设置。
activate.ts 注册 mpyhw.panel 的 WebviewViewProvider 和 mpyhw.openPanel 命令。
panel.ts 是宿主侧总线：加载 HTML、处理 Webview 消息、认证、创建 loop、连接 shim、写文件。
SessionController 管会话状态：start/retry/cancel/reset、UI prompt、事件转发、artifact 记录。
protocol-loop.ts 执行云端通过 SSE 发来的 6 个协议工具。
mpyhw-api 做 auth、credits、LLM proxy、phase prompt、包/板卡内容、telemetry。
python/shim/serve.py 只做本地设备 IO 和工具链脚本，不做 LLM 决策。

职责边界

层负责不负责入口文件
Webview UI渲染输入框、活动流、审批卡、串口、接线、环境检测不直接访问文件系统、串口、tokensrc/webview/index.html
扩展宿主VS Code API、消息路由、GitHub auth、文件写入、设备 shim不决定硬件方案src/webview/panel.ts
协议执行器把 LLM tool call 路由到 UI/FS/Host/Device/Notify不做业务规划src/core/protocol-loop.ts
后端 APIauth、credits、LLM SSE、phase recipes、包和板卡内容不直接碰用户文件和串口mpyhw-api/app/main.py
Python shimmpremote、扫描设备、烧录、串口、validate/scaffold/static/simulate 脚本不做 manifest/audit/package 选择逻辑python/shim/serve.py

6 个协议工具

工具插件路由典型用途关键代码
approval_requestUI组件确认、方案选择、需要用户输入的问题confirmApproval, addApprovalPrompt
status_updateNotify时间线进度，不阻塞postEvent, addStatusUpdate
phase_completeNotify结束当前 phase，携带 manifest，进入下一 phaserunProtocolBuild
file_operationFS写 project-manifest.json、firmware/main.py、docs/*.jsonwriteProjectFile
script_runHostvalidate、scaffold、static check、simulate、rendercreateProtocolLoop.runScript
device_commandDevice扫描、安装包、复制固件、soft reset、读串口DeviceShim

问题定位

界面没打开

看 package.json 的 contributes.views、activate.ts、registerCommands。

按钮点了没反应

看 index.html 发出的 postMessage 和 panel.ts 的 onDidReceiveMessage 分支。

LLM/生成卡住

看 llm-client.ts、protocol-loop.ts、routes_llm.py、后端 /v1/health。

协议不兼容

看 contracts/protocol_messages.json、protocol-registry.ts、/v1/tools。

文件没写出来

看 workspace-writer.ts、PROJECT_SUBDIR、file_written 事件。

设备部署失败

看 device-shim.ts、shim-process.ts、python/shim/serve.py、Doctor tab。

开发守则

先定位边界，再改代码。 UI 文案和卡片问题通常在 Webview；VS Code API、auth、文件和设备在扩展宿主；phase 行为和 prompt 在后端；协议形状在 contracts；串口和 mpremote 在 Python shim。
