Lesson 0005 · 插件的手

本地文件、设备和 UI 执行器：协议工具真正落地的地方

本课只讲本地执行器。模型发工具只是意图，真正读写文件、弹卡片、跑脚本、操作设备的是 VS Code 插件和 Python shim。

四类本地执行器

协议工具执行器关键文件

文件执行器

文件写入必须始终在 project root 下。当前输出目录是 blockless-project，避免生成物污染打开的 workspace 根目录。

file_operation(write)
  -> execFileOperation(...)
  -> deps.writeFile(path, content)
  -> panel.ts makeWorkspaceWriter(...)
  -> workspace-writer.ts writeProjectFile(...)
  -> /blockless-project/path

normalizeGeneratedArtifactPath 是防线。它拒绝绝对路径、反斜杠、空段、.、.. 和不在 allowlist 内的路径。

设备执行器

device_command(action="stream")
  -> createProtocolLoop.device(...)
  -> DeviceShim.serialReadUntil(...)
  -> ShimProcess.request("device.serial_read_until", ...)
  -> python/shim/serve.py
  -> serial output
  -> serial_output event

DeviceShim 会缓存选中的 port。部署卡片确认时，panel.ts 会先把 port 设置到 shim，再 resolve prompt，防止第一个 device tool 没端口。

脚本执行器

script_run 通过 runScript 映射到 shim 方法，例如 validate、scaffold、renderWiring、renderDiagram、runStaticCheck、runSimulate。注意：有些 phase recipe 当前明确禁止跑脚本，这时模型不应该发 script_run。

UI 执行器

所有需要用户回答的问题都应该走 approval_request。WebView 会渲染 checkbox、action button、text input。回答通过 ui_prompt_response 回到 SessionController.resolvePrompt。

核心原则：后端决定下一步要做什么；插件决定本地怎么安全执行；Python shim 只碰设备和工具链，不放 LLM、manifest、audit、package selection 逻辑。
